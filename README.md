# Автопилот «Сам решу»

Каждый день около 10:00 по Москве готовит пост по стратегии (Reels или карусель) про Сама и Надо,
присылает его в Telegram на проверку и после кнопки «Публиковать» выкладывает в Instagram.

- Контент-план — `plan.yaml` (дописывайте эпизоды в конец).
- Персонажи и правила тона — `autopilot/characters.py`.
- Эталоны персонажей — `refs/sam.png` и `refs/nado.png` (команда /refs в боте).

Команды боту: `/post` — сделать пост сейчас, `/review` — снова показать текущий черновик,
`/refs` — нарисовать эталоны заново, `/versions` — выбрать сохранённый вариант.

Согласование обязательно. `AUTO_PUBLISH` больше не отключает проверку.
Бот показывает все медиа и полный текст. Кнопка «Публиковать в Instagram» разрешает выход
показанной версии сразу при обработке кнопки; автоматического выбора будущего времени нет.
Каждый готовый вариант сохраняется вместе с независимыми копиями медиа в `posts/<id>/versions/`.
Если новый вариант хуже, нажмите «Выбрать другую версию» или отправьте `/versions`.
Выберите старый вариант: бот снова покажет именно его текст и медиа с новой кнопкой одобрения.
Выбор варианта сам по себе не публикует пост. Старые кнопки одобрения не действуют — используйте
кнопку под повторно показанной выбранной версией. Архив сохраняется и после публикации,
но опубликованный/пропущенный пост повторно этой командой не отправляется.
Сохранённые ранее только в Telegram варианты, чьи файлы уже удалены из репозитория,
автоматически восстановить нельзя. Версионирование действует с момента включения обновления. «Переделать» ожидает комментарий,
а «Пропустить» отклоняет пост. Эта кнопка публикации больше не дублирует пост во ВКонтакте;
отдельные команды `/vk_all` и сторис сохраняются.

При ошибке после начала публикации повторная отправка заблокирована. Проверьте Instagram
и Actions, затем вручную разберите запись `publication_attempts` в `state.json`; не удаляйте её,
пока не исключён уже вышедший пост. Это предотвращает автоматические дубли при потерянном ответе API.

GitHub Actions запускается с возможными задержками. Бот слушает сообщения ограниченными
сеансами (см. `.github/workflows/poll.yml`), поэтому кнопки вне сеанса могут ждать следующего запуска.
Для немедленной обработки запустите workflow «Кнопки из Telegram» вручную. Существующий бот
публикует через Instagram API; подключение Metricool в Codex не передаёт ему доступ автоматически.

Проверки без токенов, генерации и публикации: `python -m unittest discover -s tests -v`.

Правила текстов — `strategy/rules.md` (выжимка из гида). Reels оживляются в SYNTX вручную (бот присылает кадры
и промпты, клипы отправляются ответом), через Veo (переменная `VIDEO_MODE` = `veo`) или собираются из кадров
без анимации (`still`). Голоса — Google Text-to-Speech, отключаются переменной `VOICES` = `off`.


## Подготовка мини-фильмов и качество

Для мини-фильма ориентир 10–40 минут, общий предел подготовки 45 минут. Бот сообщает этапы и присылает напоминание о текущей работе примерно раз в три минуты, пока обработчик занят. Эти сообщения не означают готовность поста; команда /status во время синхронной сборки не обрабатывается.

Сценарий, принятые эталоны, кадры, клипы и озвучка сохраняются в posts/<id>/generation/. При временной ошибке повторный /post продолжает тот же пост и использует готовые части. Неудачная раскадровка сначала исправляется до картинок. Повторная переделка с тем же комментарием использует соответствующий кэш; новый комментарий создаёт отдельный вариант. Принимаемые промежуточные этапы периодически сохраняются в GitHub; этап в момент жёсткого прерывания runner может потребовать повтора.

Между историями меняются семьи и чередуются сын/дочь 14–15 лет, без привязки интересов к полу. Внутри истории используются её cast/refs. Готовые сценарии из scripts тоже адаптируются под выбранную семью. Неудачные сцены больше не заменяются случайными изображениями; при непрохождении проверки работа останавливается с объяснением.

Озвучка готовится до монтажа, длительность сцен подстраивается под реплики. Готовый фильм целиком со звуком передаётся модели-критику. Модельная оценка не заменяет одобрение владельца. При критических дефектах, низкой оценке или недоступной проверке бот показывает диагностический черновик без кнопки публикации. Предыдущие версии доступны через /versions.

Telegram по-прежнему обрабатывается сеансами GitHub Actions. Новый код начинает работать только в новом запуске, уже запущенный процесс не обновляется автоматически. Обновление не меняет провайдера сценариев: по умолчанию Gemini 2.5 Pro через Vertex AI.

Проверки: python -m unittest discover -s tests -v. Дополнительная локальная/CI-сборка без сети, генерации и публикации: ONLY_FORMATS=carousel,reel_story python smoke_constructor.py.


## Выбор площадки в Telegram

После просмотра текста и медиа доступны «Instagram», «ВК» и «Обе площадки». Нажатие одобряет текущую показанную версию для выбранных площадок при обработке кнопки. ВК доступен при подключённом VPOSTER_TOKEN и однозначно найденном сообществе. Бот показывает название/id сообщества и точный текст для ВК, если ссылка адаптирована. Кнопка ВК не отправляет пост в другие сети Впостера, даже если они есть в VPOSTER_TARGETS.

Instagram получает подтверждённую ссылку на пост. Успешный ответ Впостера означает передачу в очередь для ВК, а не подтверждение выхода. Результаты пишутся отдельно по площадкам. При неоднозначном сбое повтор этой площадки блокируется до ручной проверки; уже успешные отправки не повторяются. Старые версии и обязательное согласование сохраняются. После обновления обработчик один раз повторно показывает текущий черновик с новыми кнопками; также доступна команда /review.
